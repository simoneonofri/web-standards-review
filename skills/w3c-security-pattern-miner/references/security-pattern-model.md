# Security Pattern Model

A pattern relates context, actors, components, assets, trust boundaries, attacker capabilities, threats, expected properties, mechanisms, verification strategies, assumptions, residual risks, variants, occurrences, evidence classes, provenance, confidence, and maturity.

Maturity values are `seed`, `candidate`, `observed`, `recurring`, `validated`, and `deprecated`. The conceptual key is based on category, triggering context, trust-boundary type, threat or failure mode, and expected security property. Do not include specification-specific names in the reusable key. Preserve variants when mechanisms, attacker models, boundaries, lifecycle conditions, or verification criteria differ materially.
